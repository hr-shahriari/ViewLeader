About this example

The question: the four widgets core refuses to own — a context menu, a grip menu, key bindings and an inline text field — how does a host build them on the public surface?

  • Click a label to select it. Shift-, ⌘- or Ctrl-click toggles another one in or out of the selection.
  • Right-click a label for the host menu: edit text, reset placement, reset routing, delete.
  • Right-click a grip for the grip menu — a midpoint grip adds a bend, the vertex it becomes removes it. Grips are drawn, and hit-tested, only on a selected annotation, so select it first (or press ⌘/Ctrl+A).
  • Double-click a label to edit its text in place: Enter commits, Shift+Enter is a newline, Escape cancels.
  • Keys: arrows nudge 1 px and Shift+arrow 10 px, Delete removes the selection as one undo step, ⌘/Ctrl+A selects all, Escape clears. Undo and Redo are buttons here.
  • This page asks core for no gestures, so nothing drags: the grips are right-click targets only. Dragging them is Direct editing.
  • Orbit until an anchor swings behind the building — that leg draws dashed and dimmed (ISO 128: dashed means hidden) while the label stays at full strength.

API: editing.hitTestScreen(point) · geometry.of(id) (label, text, routeHandles) · annotations.move/update/remove/select/clearSelection · resetPlacement/resetRouting · annotations.rerouteLeg(id, legId, routing) · definitions.get(styleId) · history.transaction/undo/redo · leader.setViewportInsets({ bottom })
